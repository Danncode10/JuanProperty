# P0.4 JuanProperty Google OAuth Setup

This runbook configures local Google sign-in for the hosted JuanProperty
Supabase project. Production origins remain deferred to `[P0.7]`.

## Callback Map

```text
JuanProperty login
→ Google authorization
→ https://bnhylarpwbdwdrpctibn.supabase.co/auth/v1/callback
→ http://localhost:3000/auth/callback?next=/dashboard
→ /dashboard
```

The two callback layers are intentionally different:

- Google Cloud receives the hosted Supabase Auth callback.
- Supabase receives the JuanProperty application callback in its redirect allow
  list.

## Google Auth Platform

Use a Google Cloud project dedicated to JuanProperty.

1. In **Branding**, set the application name to `JuanProperty`, choose the
   approved support email, and add the approved developer contact email.
2. In **Audience**, keep the application in Testing while P0.4 is being
   verified and add each permitted tester under **Test users**.
3. In **Data Access**, keep only `openid`, `email`, and `profile`.
4. In **Clients**, create an OAuth client with application type
   **Web application** and name it `JuanProperty local development`.
5. Add this **Authorized JavaScript origin**:

   ```text
   http://localhost:3000
   ```

6. Add this **Authorized redirect URI** exactly, with no trailing slash:

   ```text
   https://bnhylarpwbdwdrpctibn.supabase.co/auth/v1/callback
   ```

7. Create the client and keep the Client ID and Client Secret private. Do not
   download or commit a `client_secret.json` file into this repository.

## Supabase Dashboard

Target project: `JuanProperty` (`bnhylarpwbdwdrpctibn`).

1. Open **Authentication > Sign In / Providers > Google**.
2. Enable Google and paste the Web client ID and client secret directly into
   Supabase, then save.
3. Recheck **Authentication > URL Configuration** contains:

   ```text
   Site URL: http://localhost:3000
   Redirect URL: http://localhost:3000/auth/callback
   ```

Google credentials belong only in Google Cloud and Supabase. They must not be
placed in `.env.local`, source code, chat, issue comments, logs, or screenshots.

## Production Deferral

Do not add a production JavaScript origin or Supabase application redirect until
`[P0.7]` establishes the canonical HTTPS origin. The Google redirect URI remains
the hosted Supabase callback unless the Supabase project itself changes.

## Verified Local Outcome

The administrator completed the local Google flow and confirmed that both the
initial and repeat sign-ins finish at `/dashboard`. Four tracked migrations keep
that route secure and reliable:

- `20261005032915_backfill_missing_auth_profiles.sql` creates missing
  application profiles for existing Supabase Auth users.
- `20261005035320_harden_profiles_rls.sql` removes public profile reads and
  restricts profile selection and updates to the row owner or an active
  administrator.
- `20261005103200_prevent_profile_privilege_escalation.sql` limits ordinary
  profile updates to personal fields and requires an active admin account for
  administrative RLS access.
- `20261005111500_restrict_admin_function_execution.sql` removes the legacy
  anonymous execute grant from the administrator-check helper.

The application service adds the same owner and active-admin checks for profile
lookups, and rebuilds update payloads from an explicit personal-field allowlist
as defense in depth.
