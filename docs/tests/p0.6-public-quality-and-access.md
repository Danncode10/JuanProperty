## Human verification

1. Open the home page at 375px and desktop width. Confirm the page has no horizontal overflow and clearly labels Phase 1 capabilities as planned/in development; confirm it does not promise land titles, GPS mapping, BIR tools, testimonials, customer counts, or subscription/trial terms.
2. Open the public page while signed in and inspect the rendered HTML/client props. Confirm no profile names, emails, roles, or creator repository inventory is included in the feature section.
3. Open `/dashboard` in a signed-out browser. Expected: redirect to `/login`. Sign in with an inactive profile if available; expected: also redirect to `/login`.
4. As an active member/admin, open `/dashboard/settings`; expected: normal role-filtered dashboard access. Open `/dashboard/blog/new` and `/dashboard/blog/<id>` as a member; expected: redirect to `/dashboard`. As an active admin, expected: editor routes and Blog tab work.
5. In the Blog tab, confirm there is no image-cleanup control and deleting a post does not delete storage objects. This is intentional until images are organization-scoped; no cross-organization storage deletion should be possible.
6. Inspect `/blog` and a published `/blog/<slug>` page source. Expected: canonical links identify the current route, not `/`.
