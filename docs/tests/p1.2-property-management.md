# [P1.2] Property Management Verification

## Scope

Verify that an organization owner can manage properties linked to a primary owner in the same organization, with recoverable archive/restore behavior and no permanent-delete path.

> **Verification status (2026-10-20):** Automated checks and live schema/policy/grant verification passed after updating the branch to the P1.1 merge commit. Hands-on dashboard, role-visibility, and mobile checks were deferred at the user's request.

## Human verification

1. Sign in as an account that owns an organization and open **Dashboard → Properties**. Expected: only that organization’s properties are listed.
2. With at least one active Property Owner, add a property with a name, type, address, description, and primary owner. Expected: the property appears with the correct owner and details.
3. Edit the property name, type, address, description, or primary owner and save. Expected: the new values appear after the save completes. If its current owner has been archived, that existing link may remain; new properties and owner changes can select only active owners.
4. Search by property name, type, address, or primary owner. Expected: the list filters to matching records and the result count updates.
5. Archive a property. Expected: it disappears from the active list without being deleted.
6. Enable **Include archived**, then restore the property. Expected: it is marked archived in the filtered view and returns to the active list after restore.
7. Try saving with a blank name, type, or address, and with no primary owner selected. Expected: inline validation prevents saving and identifies invalid fields.
8. If no active owner exists, open **Properties**. Expected: the empty state explains the prerequisite and the Property Owners action navigates to that tab.
9. Review the migration and live policies. Expected: RLS is enabled, `anon` cannot select either table, authenticated access is limited to the owning organization, the composite owner/org foreign key rejects cross-organization links, no DELETE policy exists, and authenticated lacks DELETE/TRUNCATE table privileges.
10. Repeat the create/edit/search/archive flows at a 375px viewport. Expected: no horizontal scrolling, visible labels and errors, and touch controls at least 48px tall.
11. Sign in with a Team Member role. Expected: **Property Owners** and **Properties** are not shown in the dashboard navigation, matching the current organization-owner-only data access policy.
