# [P1.3] Property Unit Management Verification

## Scope

Verify organization-scoped unit management under a Property, with unique unit identity, reusable default PHP rent, operational state, and archive/restore behavior. Lease occupancy and tenant assignment are deliberately not stored on the unit.

## Hands-on follow-up checklist

1. Sign in as an organization owner and open **Dashboard → Units**. Expected: only units from that owner's organization are listed.
2. Create a unit with a name, floor, bedroom/bathroom counts, monthly PHP rent, description, and operational state. Expected: the unit appears under the selected property with its entered defaults.
3. Create a second unit using the same unit number with different capitalization or surrounding spaces under the same property. Expected: the unique constraint prevents the duplicate.
4. Use the same unit number under a different property. Expected: it is allowed.
5. Edit the unit details and state. Expected: changes save, and the unit stays linked to its original property.
6. Change the default rent. Expected: only the unit's default changes; future lease records will store their own agreed rent.
7. Archive the unit, enable **Include archived**, then restore it. Expected: the record is retained and returns to the active list.
8. Confirm the UI has no tenant assignment or occupied-state field; occupancy will be derived from future Lease records.
9. Repeat create/edit/search/archive actions at a 375px viewport. Expected: no horizontal scrolling and all controls meet the project's touch-target requirements.
